# PRを出す前の確認リスト

PR作成前に、以下を上から順に確認してください。
チェックが全部付いたらPRを出してOKです。

## ブランチ・コミット

- [ ] `main` の最新を取り込んでいる（`git pull origin main` 済み、コンフリクトなし）
- [ ] 作業ブランチは `main` から切ったもの（関係ない変更を混ぜていない）
- [ ] コミットは意味ごとに分かれている（動作確認用・デバッグ用のゴミコミットなし）
- [ ] `git status` が意図どおり（不要ファイルの混入なし）

## 動作確認

- [ ] `python manage.py check` が通る
- [ ] `python manage.py migrate` が通る（必要なmigrationファイルを含めている）
- [ ] `python manage.py test` が通る
- [ ] `runserver` で関連画面を目視確認（URLと操作内容をPR本文に記載）

## 秘密情報・不要ファイル

- [ ] `.env` をコミットしていない（`.env.example` のみ更新、実値は書かない）
- [ ] `DJANGO_SECRET_KEY` やDBパスワード等の実値をコード・PR本文に書いていない
- [ ] `.venv/`、`db.sqlite3`、`__pycache__/`、`*.save` をコミットしていない
- [ ] 動作確認用の捨てファイル（例：`operation_check.md`）を残していない

## PR本文（テンプレート準拠）

- [ ] 「変更の概要」に何を・なぜを2〜3行で書いた
- [ ] 「変更内容」にできるようになったことを箇条書きした
- [ ] 「動作確認」に実行コマンド・見た画面・試した操作を書いた
- [ ] 「📚 概念リスト」は3〜7個、名前＋登場箇所のみ（説明・解説は書かない）

## CI・マージ前

- [ ] push後にGitHub Actions（Django tests）が緑になることを確認した
- [ ] マージ前に各概念へ自分の言葉の説明コメントを付ける（テンプレートのルールどおり）
